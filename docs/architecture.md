# Architecture

## What This Is

A Hub-Spoke Azure platform: a shared Hub (ACR, Key Vault, Log Analytics,
management network) peered to a single Spoke (AKS cluster + MySQL
Flexible Server). See the diagram in `README.md`.

## How It Works

1. `./deploy.sh hub apply` provisions the Hub - ACR, Key Vault, Log
   Analytics workspace, and the shared VNet.
2. `./deploy.sh db apply` provisions the MySQL Flexible Server in the
   Spoke, peered to the Hub for private DNS resolution.
3. `./deploy.sh aks apply` provisions the AKS cluster - node pool, its
   own generated SSH keypair (via the `tls` provider, stored in Key
   Vault), and an `AcrPull` role assignment so the kubelet identity can
   pull images from the Hub's ACR with no image pull secret.
4. Each `deploy.sh` invocation bootstraps its own Terraform remote state
   (a storage account in the Hub resource group) on first run.

## Key Decisions

- **Decision:** Single environment on this branch, no CI/CD pipeline.
  **Why:** The fastest path from clone to a working cluster for someone
  trying this out - no Azure AD app registration, no GitHub secrets, no
  deciding which of four environments to deploy first.
  **Revisit if:** You need staged environments or automated deploys -
  the `advanced` branch has both.
- **Decision:** AKS pulls images via its kubelet identity's `AcrPull`
  role, not ACR admin credentials.
  **Why:** No static registry password to rotate or leak.
  **Revisit if:** Never, without a strong reason - this is strictly
  better than the alternative.
- **Decision:** Node SSH keypair generated by Terraform (`tls_private_key`),
  not read from a local file.
  **Why:** A previous version read `file("../k8s")` for a gitignored,
  never-committed file - broke `terraform validate`/`plan` on any fresh
  clone, including CI. Generating it removes the local-file dependency
  entirely.
  **Revisit if:** Never - this is strictly more portable.

## Known Risks / Rough Edges

- Real, billed Azure infrastructure from the first `apply` - no free
  tier. `./deploy.sh <component> destroy` when you're done.
- `authorized_ip_range` defaults to one specific IP in
  `aks-main-weu-terraform.tfvars` - update it to your own before relying
  on it as an access restriction.
- ACR's `network_rule_set` only supports IP-based rules in the pinned
  provider version (VNet-scoped rules were removed upstream) - the AKS
  subnet isn't network-restricted at the registry level, only
  identity-restricted via the `AcrPull` role assignment.
